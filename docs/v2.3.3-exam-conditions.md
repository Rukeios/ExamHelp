# v2.3.3: Mock exams under exam conditions

A setting on the Mock exam page, off by default. With it on, a mock ends the way a real exam does: a score and a breakdown, with no answers.

## What changes when it is on
| | Setting off (as before) | Setting on |
|---|---|---|
| During the exam | No feedback | No feedback; the header says "exam conditions" |
| Result screen | Score, per-domain breakdown, every missed question with its answer and explanation | Score, per-domain breakdown, and the five levels where the most points were lost, each with its Pocket Note titles and links to the lesson |
| Missed questions | Added to Review; "Drill my missed questions" button | Not added to Review; no drill button |
| Saved attempt | Per-question results kept | `strict:true`, `items:[]`. Score, points and per-domain numbers are kept |
| Results file | None | Download or share from the result screen |

Because the saved attempt holds no per-question results, nothing else in the app can show which questions were missed: Review, Most missed, question history and domain accuracy on Progress don't see them. The mock's score still appears on Progress, and XP is awarded as usual.

The setting is `state.mockStrict`, so it travels with backups and device transfers. A run keeps the setting it started with.

## "Where you lost the most points"
Ranked by points lost, per level, top five, levels with less than one point lost left out. It is at level granularity because the question bank ties each question to a level, not to a single Pocket Note. The Pocket Note titles listed under a level are that level's notes, not a claim that each one was missed. A finer breakdown needs the results file.

## The results file
`rukeios-study-<track>-mock-<date>.json`, one line of JSON.

```
{
  "format": "rukeios-mock-result", "v": 1,
  "app": "Rukeios Study", "appVersion": "2.3.3",
  "taken": "<ISO time>", "exam": "SC-900", "track": "sc", "examConditions": true,
  "summary": {
    "percent": 64, "points": 53, "pointsMax": 83, "questions": 50, "unanswered": 0,
    "minutesUsed": 41, "minutesAllowed": 45,
    "byDomain": { "<domain>": { "correct": 5, "total": 9, "pct": 56 } },
    "mostPointsLost": [ { "level": 7, "title": "...", "pointsLost": 9, "pointsAvailable": 16 } ]
  },
  "note": "...",
  "detailEncoding": "base64-utf8-json",
  "detail": "<base64>"
}
```

`summary` is readable and holds no answers. `detail` is base64 of UTF-8 JSON, so the answers can't be read by opening the file. Decoded:

```
{ "items": [ {
    "n": 1, "key": "<question id>", "level": 4, "levelTitle": "...", "domain": "Entra",
    "flagged": false, "answered": true, "pointsEarned": 1, "pointsMax": 1,
    "type": "multiple-choice", "question": "...", "options": ["..."],
    "yourAnswer": "...", "correctAnswer": "...", "correct": true, "why": "..."
} ] }
```

Exam-style items have `type` `yes-no`, `drop-down`, `choose-N` or `matching`, and a `parts` array in place of `options`, `yourAnswer` and `correctAnswer`. Each part has `prompt`, `yourAnswer`, `correctAnswer` and `correct`, plus `why` for Yes/No statements and `options` for drop-downs and matches.

To read it: `JSON.parse(atob(file.detail))` in a browser, or `json.loads(base64.b64decode(f["detail"]))` in Python. The encoding is friction, not security: anyone who wants the answers can decode them.

The most recent file is also kept in the browser (`sprint.v2.mockfile`) and offered again on the Mock exam page. It is not part of backups or device transfers.

## Tests
- New (`t233`): the setting is off by default, labelled and persists; a default mock is unchanged; an exam-conditions mock shows no answers anywhere, saves no per-question results, leaves Review untouched and still awards XP; the file name, summary and decoded detail are checked against the answers clicked and the score; the weakest levels are recomputed from the detail; the last file can be downloaded again; turning the setting off restores the review.
