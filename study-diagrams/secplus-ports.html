Ports and protocols, grouped by job

Security+ (SY0-701) PBQs and questions ask which port a job uses, and which secure protocol replaces an old one. Learn them by job, not as one long list. Crossed-out ports are the insecure ones you replace.

Managing devices

Logging in to servers and network gear.

22SSHEncrypted command line. SFTP and SCP ride on it too.
23TelnetClear text, passwords visible. Replace with SSH.
3389RDPWindows remote desktop.
161 / 162SNMP161 queries, 162 traps. Use SNMPv3 for encryption.

Web and email

Browsing, sending and reading mail.

80HTTPClear text web.
443HTTPSWeb over TLS.
25 / 587SMTP25 server to server, 587 submission with STARTTLS. 465 is SMTPS.
993 / 995IMAPS / POP3SEncrypted mail reading. Plain IMAP is 143, POP3 is 110.

Signing in, directories, file shares.

THE SECURE SWAP: WHAT REPLACES WHAT
Telnet 23 → SSH 22
HTTP 80 → HTTPS 443
FTP 21 → SFTP 22
LDAP 389 → LDAPS 636
IMAP 143 → IMAPS 993
SNMPv1/v2c → SNMPv3
Firewall tables: rules are read top to bottom, the first match wins, and traffic that matches nothing is dropped by the implicit deny. A broad deny placed above a narrow allow hides the allow.
The trap: SFTP is SSH on 22. FTPS is FTP with TLS on 989/990. Same goal, different protocols and ports.
Pattern: the secure version usually gets a different number: 80→443, 389→636, 143→993, 110→995. The exception is SFTP, which shares SSH's 22 because it runs inside SSH.
